1. 整体业务流程图

flowchart TD A[创建处方

endSoak] D --> E[开始煎药

MQTT / HTTP] G --> H{任务状态} H -->|BOUND| I[自动推进
BOUND → PROCESSING] H -->|PROCESSING| J[煎药进行中] I --> J J --> K[结束煎药

2. Task（任务）实体状态图

stateDiagram-v2 [*] --> PENDING: 创建处方自动生成 PENDING --> SOAKING: startSoak(开始泡药) SOAKING --> SOAKED: endSoak(结束泡药) SOAKED --> PROCESSING: startDecoct(开始煎药) PENDING --> BOUND: bindDevice(扫码绑定设备) BOUND --> PROCESSING: 温度上报自动推进 PROCESSING --> DECOCTED: endDecoct(结束煎药) DECOCTED --> POURING: startPour(开始出液) POURING --> WRAPPING: endPour(结束出液) WRAPPING --> COMPLETED: endWrap(结束包装) PENDING --> CANCELLED: forceStatus(强制取消) SOAKING --> CANCELLED: forceStatus(强制取消) SOAKED --> CANCELLED: forceStatus(强制取消) BOUND --> CANCELLED: forceStatus(强制取消) PROCESSING --> CANCELLED: forceStatus(强制取消) DECOCTED --> CANCELLED: forceStatus(强制取消) POURING --> CANCELLED: forceStatus(强制取消) WRAPPING --> CANCELLED: forceStatus(强制取消) COMPLETED --> [*]: 任务结束 CANCELLED --> [*]: 任务取消 note right of PROCESSING 煎药中: - currentTemp 实时更新 - 设备状态 BUSY - 温度超限触发告警 end note note right of WRAPPING 包装阶段: - 可绑定包装机 - 结束自动打印标签 end note
Task 状态值：PENDING SOAKING SOAKED BOUND PROCESSING DECOCTED POURING WRAPPING COMPLETED CANCELLED

3. Device（设备）实体状态图

stateDiagram-v2 [*] --> IDLE: 设备注册/创建 IDLE --> BUSY: 绑定任务 BUSY --> IDLE: 任务阶段结束释放 BUSY --> FAULT: 设备故障上报 FAULT --> IDLE: 故障恢复 note right of IDLE 空闲状态: - 可被新任务绑定 - currentTemp 可能仍有读数 end note note right of BUSY 忙碌状态: - 已绑定到某个任务 - 不可被其他任务占用 end note note right of FAULT 故障状态: - faultCode 有值 - 需人工干预恢复 end note
Device 状态值：IDLE BUSY FAULT   |   设备类型：1=煎药机 2=包装机 4=打印机

4. Print（打印）状态图

stateDiagram-v2 [*] --> PENDING: 包装完成触发自动打印 PENDING --> PRINTING: doPrintLabel(开始打印) PRINTING --> PRINTED: 打印成功 PRINTING --> FAILED: 打印机故障/不可用 FAILED --> PENDING: retryPrint(重试打印) PENDING --> PRINTING: printLabel(手动打印) PRINTED --> [*]: 打印完成 note right of PENDING 待打印: - 包装完成时自动触发 - 或手动调用打印接口 end note note right of FAILED 打印失败原因: - 打印机状态非 IDLE - 未找到关联打印机 - 通信异常 end note
Print 状态值（Task.printStatus）：null/PENDING PRINTING PRINTED FAILED

5. 核心业务时序图

sequenceDiagram autonumber participant Op as 操作员/PDA participant API as 后端 API participant DB as 数据库 participant Dev as 智能设备 participant MQTT as MQTT Broker Op->>API: 1. 创建处方 API->>DB: 插入 Prescription API->>DB: 自动生成 Task (PENDING) API-->>Op: 返回任务ID Op->>API: 2. 开始泡药 (startSoak) API->>DB: Task → SOAKING API-->>Op: 成功 Op->>API: 3. 结束泡药 (endSoak) API->>DB: Task → SOAKED API-->>Op: 成功 Op->>API: 4. 开始煎药 (startDecoct) API->>DB: 查找/创建设备 API->>DB: Device → BUSY API->>DB: Task → PROCESSING API-->>Op: 成功 Dev->>MQTT: 5. 上报温度 (85.5℃) MQTT->>API: 温度消息 API->>DB: 更新 currentTemp API->>DB: 记录温度曲线 API->>DB: 温度告警检测 Op->>API: 6. 结束煎药 (endDecoct) API->>DB: Task → DECOCTED API->>DB: Device → IDLE (释放) API-->>Op: 成功 Op->>API: 7. 开始出液 (startPour) API->>DB: Task → POURING API-->>Op: 成功 Op->>API: 8. 结束出液 (endPour) API->>DB: Task → WRAPPING API-->>Op: 成功 Op->>API: 9. 开始包装 (startWrap) API->>DB: 查找/创建包装机 API->>DB: 包装机 → BUSY API->>DB: Task → WRAPPING API-->>Op: 成功 Op->>API: 10. 结束包装 (endWrap) API->>DB: Task → COMPLETED API->>DB: 包装机 → IDLE API->>DB: 查找默认打印机 API->>DB: 打印机 → BUSY API->>DB: printStatus → PRINTING API->>DB: printStatus → PRINTED API->>DB: 打印机 → IDLE API-->>Op: 成功 (含打印结果)
说明：橙色步骤为操作员主动触发，紫色步骤为设备自动上报，绿色步骤为系统自动处理（打印）。

6. DeviceAlarm（设备告警）状态图

stateDiagram-v2 [*] --> UNHANDLED: 温度超限/故障触发 UNHANDLED --> HANDLED: 人工确认处理 HANDLED --> [*]: 告警关闭 note right of UNHANDLED 未处理 (status=0): - TEMP_HIGH: 温度超过阈值 - TEMP_LOW: 温度低于阈值 - 同类型未处理告警不再重复创建 end note
Alarm 状态值：0=未处理(UNHANDLED) 1=已处理(HANDLED)   |   告警类型：TEMP_HIGH TEMP_LOW 等
