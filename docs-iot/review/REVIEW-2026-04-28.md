## 三、HIGH 问题清单

### 业务正确性
- 质检 4 分支用中文 `switch-case("通过"/"让步放行"/"返工"/"报废")`，空格/编码差异即导致匹配失败
- 返工分支未调 `EquipmentService.reserveDevice()`，返工任务的设备会被新任务抢占
- 返工时未清空 `decoctDeviceId/packageDeviceId`，强制完成可能导致设备长期被占
- `tryRecordConsume()` 失败仅打日志不回滚，库存与生产数据可能不一致

### 接口/契约
- API 文档 183 行 vs 60+ 端点，覆盖率 ~50%；登录/设备 reserve/温度曲线/SPI 全部缺失
- `EquipmentService.queryDevice()` 等接口返回 `Object`，调用方需强转——类型安全归零
- SPI 接口无版本号，未来不能滚动升级

### MQTT/IoT
- 订阅 topic 与发布 topic 格式不一致（`device/+/status` vs `/openygt/*/.../status`）
- 默认 QoS=0，弱网下温度/告警消息会丢
- 心跳超时机制 EQ-014 在文档中已设计，代码未实现
- 温度阈值三层继承（sys_config→device→scheme）未实现

### 数据库
- SQLite/MySQL 方言差异未做抽象层
- 软删除 `deleted` 字段对业务唯一约束（trace_code、print_device_id）的影响未处理
- V5 迁移无回滚脚本
- prod_task 8 个冗余字段标记删除但实体未同步

### 测试
- 单测/主码 = 28/176 ≈ 16%，production 模块仅 4 个测试，print/quality 各 1 个
- 无并发测试（`ConcurrentBindTest` 实际为空骨架）
- 无数据库迁移测试
- `BaseProductionTest` 共享 H2 但无 `@Transactional` 自动回滚，存在污染

### 异常/可观测性
- 多处 `catch(Exception e) { log.debug() }` 吞错
- 日志缺 traceId/tenantId，跨模块排障困难
- 无熔断/限流（Resilience4j），EquipmentService 故障会拖垮 production

### 依赖安全
- `jjwt 0.9.1`（2017 年）— 升级到 0.12.x 但需评估 Java 8 兼容
- `Paho 1.2.5` — 缺 QoS2 幂等支持
- 未配置 MQTT 用户名密码

### 6.2 架构设计评审（C）

**模块边界**
- [严重] `dms-rbac` 在 V3.0 架构文档 9 模块列表中消失，但 pom 实际有 11 模块
- [严重] `dms-common` 承载过多职责（接口+DTO+枚举+异常+基类），中央仓库反模式
- [高] `dms-production` 依赖 `dms-inventory` 但文档无此箭头
- [中] `dms-analytics` 预留状态但 pom 已含，目录为空

**跨模块契约**
- [严重] 跨模块全为 in-process Bean 注入，无断路器、无服务隔离
- [高] `MqttClient` 单例 ClientId 硬编码 "dms-backend"，集群下连接互踢
- [高] SPI 接口无版本号，无法滚动升级

**状态机与并发**
- [严重] 12 步状态机缺合法转移矩阵，无法区分"业务错误"与"非法操作"
- [严重] `prod_task.status` 无悲观锁，并发绑定竞态
- [高] `@Transactional` 默认 READ_COMMITTED，状态变更可能读到脏数据
- [中] history 与 task 状态不一致风险（无事务原子性保证）

**MQTT**
- [严重] 单 ClientId + topic 无租户隔离
- [中] 无 QoS 配置，默认 0
- [中] topic 格式 `device/{deviceId}/status` 无租户标记

**数据库**
- [高] SQLite/MySQL 方言差异未抽象
- [高] 软删除字段对唯一索引的影响未处理
- [中] BaseEntity.deleted 为 INTEGER 而非 BOOLEAN，无 Schema 层保障
- [中] V5 无回滚脚本

**未来扩展**
- [严重] 声称"模块化单体→独立打包→微服务"，但共用 DB + in-process 调用 + 无分布式事务，三大陷阱已埋

### 6.4 源码质量评审（B）

**CRITICAL**
- `JwtUtil.java:26` 硬编码 JWT 密钥

- 调度器全 `@Scheduled` 无分布式锁

**HIGH**
- 异常日志缺 taskId/deviceId/traceId

- MQTT 订阅与发布 topic 格式不一致

**长类 / 长方法**
1. `TaskServiceImpl.java` ~600 行，应拆为 SoakService/DecoctService/WrapService
2. `MqttConfig.java` ~162 行，应拆 Topic Parser + Message Router
3. `doQualityInspect()` ~30 行，4 层 if-else 应改 Strategy 模式

**依赖安全**
- `jjwt 0.9.1` (2017) — CVE-2022-23529 风险面，需升级至 0.12.x（Java 8 兼容性需评估）
- `Paho 1.2.5` (2021) — 缺 QoS2 幂等支持
- MQTT broker 无认证

**安全检查**
- ✓ SQL 注入：所有 `@Select` 使用 `#{param}` 参数化
- ✓ DatabaseInitConfig 未直接执行用户输入
- ✗ 静态 HTML 直接暴露 API endpoint，建议加反向代理鉴权

### 9.4 C-5 修复：MQTT ClientId / Topic

```java
// dms-equipment/src/main/java/cn/org/openygt/equipment/config/MqttConfig.java
@Bean
public MqttClient mqttClient(@Value("${mqtt.broker-url}") String brokerUrl,
                             @Value("${mqtt.client-id-prefix:dms-backend}") String prefix,
                             @Value("${spring.application.instance-id:#{T(java.util.UUID).randomUUID().toString()}}") String instanceId) {
    String clientId = prefix + "-" + instanceId.substring(0, 8);
    MqttClient client = new MqttClient(brokerUrl, clientId, new MemoryPersistence());
    MqttConnectOptions opts = new MqttConnectOptions();
    opts.setAutomaticReconnect(true);
    opts.setCleanSession(false);   // 关键：保留订阅状态
    opts.setKeepAliveInterval(30);
    if (mqttUsername != null) opts.setUserName(mqttUsername);
    if (mqttPassword != null) opts.setPassword(mqttPassword.toCharArray());
    client.connect(opts);

    // 共享订阅，集群消费分摊（EMQX 4.x+ 支持）
    client.subscribe("$share/dms-cluster/openygt/+/device/+/status", 1);
    client.subscribe("$share/dms-cluster/openygt/+/device/+/heartbeat", 1);
    client.subscribe("$share/dms-cluster/openygt/+/device/+/fault", 2);
    return client;
}
```

Topic 规约：`/openygt/{tenantId}/device/{deviceCode}/{type}`，type ∈ `status|heartbeat|command|response|fault`。

### 9.6 C-7 修复：设备绑定 SELECT FOR UPDATE

```java
// dms-equipment/src/main/java/cn/org/openygt/equipment/mapper/EqDeviceMapper.java
@Select("SELECT * FROM eq_device WHERE device_code = #{code} AND deleted = 0 FOR UPDATE")
EqDevice selectByCodeForUpdate(@Param("code") String deviceCode);

// TaskServiceImpl.java
@Transactional(isolation = Isolation.READ_COMMITTED)
public void bindDevice(Long taskId, String deviceCode) {
    EqDevice device = eqDeviceMapper.selectByCodeForUpdate(deviceCode);  // 行锁
    if (!"IDLE".equals(device.getStatus())) {
        throw new BusinessException("DEVICE_NOT_IDLE", "设备当前不可用");
    }
    device.setStatus("BUSY");
    device.setCurrentTaskId(taskId);
    eqDeviceMapper.updateById(device);
    // ...
}
```

### 9.7 集成测试模板

```java
// dms-production/src/test/java/cn/org/openygt/production/service/ConcurrentBindTest.java
@SpringBootTest
@Transactional
@Rollback
class ConcurrentBindTest extends BaseProductionTest {

    @Test
    void testTwoThreadsBindSameDevice_onlyOneSucceeds() throws Exception {
        prepareDevice("D001", "IDLE");
        Long taskA = prepareTask("待泡药");
        Long taskB = prepareTask("待泡药");

        ExecutorService pool = Executors.newFixedThreadPool(2);
        CountDownLatch start = new CountDownLatch(1);
        AtomicInteger ok = new AtomicInteger();
        AtomicInteger fail = new AtomicInteger();

        Callable<Void> bind = () -> {
            start.await();
            try {
                taskService.bindDevice(taskA, "D001");
                ok.incrementAndGet();
            } catch (BusinessException e) {
                fail.incrementAndGet();
            }
            return null;
        };
        Future<?> f1 = pool.submit(bind);
        Future<?> f2 = pool.submit(bind);
        start.countDown();
        f1.get(5, TimeUnit.SECONDS);
        f2.get(5, TimeUnit.SECONDS);

        assertEquals(1, ok.get(), "仅一个线程应绑定成功");
        assertEquals(1, fail.get(), "另一个应得到 DEVICE_NOT_IDLE");
    }
}
```
