## 3. 开发流程

```
概要设计 → 架构师审核 → 详细设计 → 架构师审核 → 开发 → 测试
```

### 3.1 流程说明

| 阶段 | 产出物 | 审核人 | 通过标准 |
|------|--------|--------|---------|
| 概要设计 | `kimi0X-概设.md` | 架构师 | 模块边界清晰、接口定义合理、与现有代码兼容 |
| 详细设计 | `kimi0X-详设.md` | 架构师 | 类图/方法签名完整、数据库变更明确、测试方案可行 |
| 开发 | 代码 + 单元测试 | kimi01 | mvn compile 通过、mvn test 通过 |
| 测试 | 测试报告 | 架构师 | 覆盖率 > 80%、全流程回归通过 |

### 3.2 文档提交位置

```
docs/tasks/
├── kimi02-概设.md          # kimi02 概要设计
├── kimi02-详设.md          # kimi02 详细设计
├── kimi03-概设.md
├── kimi03-详设.md
├── kimi04-概设.md
├── kimi04-详设.md
├── kimi01-测试方案.md      # kimi01 测试方案
└── kimi0X-reply.md         # 沟通回复（已有）
```

## 5. 概要设计模板

各 kimi 成员按以下模板编写概设文档：

```markdown
# kimi0X 概要设计 - [模块名称]

## 1. 需求范围
- 对应需求编号（参考需求规格说明书）
- 功能边界说明

## 2. 模块设计
- 新增/修改的包和类
- 与现有代码的关系

## 3. 接口设计
- 新增 REST API 列表
- 请求/响应格式

## 4. 数据库设计
- 新增/修改的表
- 字段定义

## 5. 与其他模块的交互
- 调用哪些现有接口
- 被哪些模块调用

## 6. 技术方案
- 关键技术选型和理由
- 难点和风险
```
