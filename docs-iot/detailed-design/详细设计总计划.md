## 一、代码现状与目标差距（关键前提）

通过代码审计发现，**当前代码与 V1.4 文档存在显著差距**。详细设计必须同时回答两个问题：
1. **目标状态是什么**（按 V1.4 文档实现）
2. **从现状怎么改**（代码差距修复路径）

### 1.1 致命级差距（不修复则系统无法启动或运行错误）

| 问题 | 影响 | 修复优先级 |
|------|------|-----------|
| `dms-quality` 内部 `Task` 实体映射表名 `task`（V4 已改为 `prod_task`） | **启动即抛 "no such table: task"** | P0-1 |
| `dms-print` 直接 `import` `dms-production` 的 `TaskMapper`/`TaskStatusHistoryMapper`/`Task` | **编译通过但违反模块边界** | P0-2 |
| `dms-system` 密码**明文存储**，无 JWT 认证 | **医疗合规违法（个保法/GSP）** | P0-3 |
| `dms-common` 缺少 `BaseAuditEntity`、`InspectionResultType` 枚举、`EqDeviceDTO` 等 | **下游模块无法按文档编译** | P0-4 |

### 1.2 高危差距（功能缺陷或架构债务）

| 问题 | 影响 | 修复优先级 |
|------|------|-----------|
| `TaskServiceImpl` 仍用 `synchronized`，未改为数据库悲观锁 | 单 JVM 有效，无法支撑后续拆分 | P1-1 |
| `EquipmentService` 返回值仍为 `Object`，未实现 `reserveDevice` | 返工设备可能被抢占 | P1-2 |
| `SoakTimeoutScheduler` 未从 `sys_config` 读取超时配置 | 超时阈值硬编码 | P1-3 |
| `DatabaseInitConfig` 使用字符串拼接 SQL | SQL 注入风险（虽然 script 来源硬编码） | P1-4 |
| `MqttConfig` 未解析 JSON payload，直接 `new BigDecimal(payload.trim())` | 无法处理真实设备的状态 JSON | P1-5 |

### 1.3 详细设计策略

**策略："文档驱动 + 差距清单"**

每份详细设计文档包含三个部分：
1. **目标设计**：按 V1.4 文档的完整详细设计（开发人员按此开发新功能）
2. **现状差距表**：当前代码与目标的差异清单（开发人员按此修复现有代码）
3. **迁移路径**：从现状到目标的修改步骤（文件级、方法级）

## 四、协作与集成规范

### 4.1 开发顺序（有向无环）

```
dms-common（先完成，其他模块依赖）
    ↓
dms-system（JWT 认证过滤器，dms-app 依赖）
dms-masterdata（无其他业务依赖）
    ↓
dms-equipment（EquipmentService SPI）
    ↓
dms-production（依赖 EquipmentService + PrintService + QualityService）
    ↓
dms-quality（依赖 ProductionQueryService）
dms-print（依赖 ProductionQueryService）
    ↓
dms-analytics（依赖所有 SPI）
```

### 4.2 接口冻结原则

- **dms-common 中的 SPI 接口冻结后不得随意修改**。如需修改，必须经过架构师审批，并同步更新所有实现方和调用方。
- 详细设计阶段的前 3 天为 **SPI 接口冻结期**，各模块负责人必须确认接口满足需求。

### 4.3 数据库迁移脚本规范

- 命名：`V{版本号}__{模块缩写}_{描述}.sql`
- 双版本：每条 DDL 必须提供 SQLite 和 MySQL 两种语法（注释标明）
- 幂等性：每条脚本必须支持重复执行不报错（`CREATE TABLE IF NOT EXISTS`、`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）

每份详细设计文档完成后，需通过以下检查：

- [ ] 所有 REST API 端点都有明确的 RequestDTO / ResponseDTO 定义

- [ ] 数据库 DDL 可在 SQLite 和 MySQL 上执行通过
- [ ] 核心流程有文字版时序图，涉及跨模块调用的标出 SPI 方法名
- [ ] 并发控制策略明确（悲观锁的 SQL、乐观锁的版本号字段）
- [ ] 单元测试策略覆盖正常路径 + 至少 2 条异常路径
- [ ] 迁移路径清单可执行（开发人员按清单逐项修改即可达到目标）
