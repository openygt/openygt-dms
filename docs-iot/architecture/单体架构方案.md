## 1. 架构概述

### 1.1 部署方式

```
┌─────────────────────────────────────────────────────────────┐
│                    单体应用 (单JAR)                          │
│  ┌───────────────────────────────────────────────────┐  │
│  │  DecoctionApplication.jar                      │  │
│  │  Port: 8080                                  │  │
│  └───────────────────────────────────────────────────┘  │
│                         ▲                                 │
└─────────────────────────┼─────────────────────────────┘
                          │
        ┌───────────────┴───────────────┐
        ▼                               ▼
┌──────────────┐               ┌──────────────┐
│  EMQX        │               │  SQLite      │
│  (1883)      │               │  decoction.db│
└──────────────┘               └──────────────┘
```

### 1.2 优势

| 优势 | 说明 |
|------|------|
| 部署简单 | 一个JAR包，一键启动 |
| 开发效率 | 本地调试方便，无需多服务协同 |
| 运维简单 | 无服务间通信问题 |
| 事务一致性 | 本地事务即可 |

### 1.3 代码组织方式

推荐使用 **Maven多模块** + **包名分离**：

```
decoction-system/          # 父项目
├── decoction-common/     # 公共模块（DTO/Entity/工具类）
├── decoction-iot/        # 物联网模块
├── decoction-workorder/   # 工单管理模块
└── decoction-app/        # 启动模块（打包为单JAR）
```

## 5. 模块间协作

### 5.1 直接依赖调用（推荐）

```java
// 工单模块依赖物联网模块
package com.decoction.workorder.service;

import com.decoction.iot.service.DeviceService;
import com.decoction.iot.dto.DeviceStatusDTO;

@Service
public class WorkOrderServiceImpl implements WorkOrderService {
    
    @Autowired
    private DeviceService deviceService;  // 直接注入物联网服务
    
    @Autowired
    private WorkOrderMapper workOrderMapper;
    
    @Transactional
    public void assignDevice(Long orderId, String deviceId) {
        WorkOrder workOrder = workOrderMapper.selectById(orderId);
        if (workOrder == null) {
            throw new WorkOrderNotFoundException(orderId);
        }
        
        // 调用物联网模块检查设备状态
        DeviceStatusDTO deviceStatus = deviceService.getDeviceStatus(deviceId);
        if (!"IDLE".equals(deviceStatus.getStatus())) {
            throw new DeviceNotAvailableException(deviceId, deviceStatus.getStatus());
        }
        
        // 下发设备指令
        DeviceCommand command = new DeviceCommand();
        command.setCommandType("START");
        command.setOrderId(orderId.toString());
        DeviceCommandResult result = deviceService.sendCommand(deviceId, command);
        
        if (!result.getSuccess()) {
            throw new DeviceCommandFailedException(deviceId, result.getMessage());
        }
        
        // 更新工单状态
        workOrder.setDeviceId(deviceId);
        workOrder.setStatus("ASSIGNED");
        workOrderMapper.updateById(workOrder);
    }
}
```

## 7. 部署方式

### 7.1 构建与运行

```bash
# 构建整个项目
cd decoction-system
mvn clean package -DskipTests

# 启动应用
java -jar decoction-app/target/decoction-app-1.0.0-SNAPSHOT.jar

# 或带配置启动
java -jar decoction-app/target/decoction-app-1.0.0-SNAPSHOT.jar \
  --server.port=8080 \
  --spring.datasource.url=jdbc:sqlite:/data/decoction.db \
  --emqx.broker.url=tcp://emqx:1883
```

### 7.2 Docker部署

```dockerfile
# 多阶段构建
FROM maven:3.8-openjdk-8 AS builder
WORKDIR /app
COPY pom.xml .
COPY decoction-common ./decoction-common
COPY decoction-iot ./decoction-iot
COPY decoction-workorder ./decoction-workorder
COPY decoction-app ./decoction-app
RUN mvn clean package -DskipTests

FROM openjdk:8-jre-slim
WORKDIR /app
COPY --from=builder /app/decoction-app/target/decoction-app-1.0.0-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## 8. 优势对比

| 特性 | 独立工程 | 单体应用 |
|------|---------|---------|
| 部署复杂度 | 2个JAR | 1个JAR |
| 开发调试 | 需要两个服务 | 一个服务即可 |
| 模块耦合 | 松耦合 | 包名隔离 |
| 事务一致性 | 分布式事务 | 本地事务 |
| 独立扩展 | 独立扩展 | 整体扩展 |
| 模块边界 | 明确 | 包名隔离 |

## 9. 未来扩展路径

如果将来需要拆分为微服务：

```
单体应用
    ↓
模块化单体（当前方案）
    ↓
模块化服务（可独立打包）
    ↓
微服务（独立部署）
```

当前方案让代码保持模块化，未来需要时可以：
1. 将每个模块独立打包
2. 通过Feign/RestTemplate进行服务间调用
3. 引入服务发现和配置中心

## 10. 总结

单体架构 + Maven多模块是最适合当前项目的方案：

1. **一个JAR运行**，部署简单
2. **代码模块化分离**，便于团队协作
3. **直接依赖调用**，无需HTTP/MQTT开销
4. **本地事务**，数据一致性有保障
5. **未来可拆分**，为微服务预留路径
