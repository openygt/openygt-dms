# OpenYGT-DMS 智能煎药管理系统

[![License](https://img.shields.io/badge/license-AGPL--3.0-blue.svg)](LICENSE)
[![Docker](https://img.shields.io/badge/docker--compose-ready-2496ED.svg)]()

面向中药房汤剂煎煮场景的全流程智能管理系统，覆盖从处方接收到患者取药的完整链路。

---

## 快速开始

```bash
# 一键启动（Docker Compose）
git clone https://gitee.com/openygt/openygt-dms.git
cd openygt-dms
docker compose up -d

# 访问地址
# Web 管理端：http://localhost:5176
# 默认账号：admin / admin123
```

## 技术栈

| 层级 | 技术选型 |
|------|----------|
| 前端（Web） | Vue 3 + TypeScript + Element Plus |
| 前端（PDA） | uni-app（Vue 3），支持 H5、Android PDA 设备 |
| 后端 | Spring Boot 3 + MyBatis-Plus |
| 数据库 | MySQL 8.0（信创适配达梦 DM8 进行中） |
| 消息 | MQTT（设备通信） |
| 部署 | Docker Compose 一键部署 |

## 📋 开发与测试文档化制度（强制）

> 以下制度由产品经理制定，全体团队成员（开发、测试、架构）必须遵守。
>
> **🔴 环境隔离禁令（最高优先级）**
> - **一人一目录**：每位成员只操作自己的工作目录（如 `openygt-dms-04`）
> - **一目录一端口**：每个目录对应固定端口，严禁跨界占用他人端口
> - **禁止跨界**：测试工程师不得编译/重启/修改开发人员目录中的代码和配置
> - **禁止动他人进程**：严禁 kill、stop、restart 其他成员运行的服务进程
> - **违规后果**：破坏他人环境的，须立即恢复并书面检讨

### 两种测试模式

| 模式 | 场景 | 测试工程师职责 | 禁止事项 |
|------|------|---------------|----------|
| **模式 A：测开发人员新代码** | 开发人员目录已启动服务 | 只用 curl 测试，不动代码/配置/进程 | 禁止编译、禁止重启、禁止改配置、禁止杀进程 |
| **模式 B：自己拉代码测** | 在自己目录拉最新代码 | 完整环境搭建 + 测试脚本编写 + 执行 | 禁止动他人目录 |

> 默认采用 **模式 A**。如需模式 B，须产品经理明确授权。

### 1. 计划必须写文档
- 任何迭代开始之前，必须输出《开发执行计划》文档
- 文档包含：目标范围、模块清单、数据库变更、接口变更、依赖关系、排期
- 未写计划文档的迭代，测试工程师有权拒绝介入

### 2. 方案必须写文档
- 任何技术方案（重构、新模块、数据库迁移、API 调整）必须输出方案文档
- 文档包含：背景、方案对比、影响范围、回滚策略、测试策略
- 方案文档必须经过产品经理或架构师评审后方可执行

### 3. 工作结束必须有总结文档
- 每个任务/迭代结束后，负责人必须输出《工作总结》文档
- 文档包含：已完成项、Bug 清单及修复说明、遗留问题、下一步建议
- 总结文档提交后，产品经理进行验收确认

### 4. 团队沟通通过文档而非口头
- 开发人员 ↔ 测试人员 ↔ 架构师之间的信息传递，优先通过文档
- 禁止让产品经理当传话筒转发技术细节
- 紧急问题可即时沟通，但事后必须补文档留档

### 5. 文档存放规范（🔴 禁令级）

> **所有文档必须放在统一目录，禁止随手乱放。违反者 = 文档作废，需要重写。**

#### 5.2 命名规则

| 层级 | 格式 | 示例 |
|------|------|------|
| 日期目录 | `YYYYMMDD` | `20260508` |
| 事项目录 | `序号-事项名称-负责人` | `00系统的表结构得规范-产品经理` |
| 文档文件 | `主题-状态.md` | `表名规范执行疑问-待架构师决策.md` |
| 执行单 | `执行单-主题.md` | `执行单-masterdata-RENAME.md` |
| 报告 | `报告-主题.md` | `报告-API测试-20260508.md` |

#### 5.3 禁止事项

- ❌ **禁止**把文档放在项目根目录（`README.md` 除外）
- ❌ **禁止**把文档放在 `src/`、`target/`、`node_modules/` 里
- ❌ **禁止**用 `新建文件夹`、`文档1`、`未命名` 等不知所云的目录名
- ❌ **禁止**文档散落在个人桌面、微信文件、邮件附件里
- ❌ **禁止**同一事项拆成多个目录存放

#### 5.4 违规后果

- 文档放错位置 = **视为未写**，产品经理不验收
- 命名不规范 = **退回重命名**
- 找不到文档 = **责任自负**，不补档
