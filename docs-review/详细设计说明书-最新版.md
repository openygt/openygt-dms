## 2. 启动与基础配置设计

### 2.1 启动入口

入口类：
- [DmsApplication.java](/data2/docker/decoction/openygt-dms-a/dms-app/src/main/java/cn/org/openygt/DmsApplication.java:1)

设计：
- 通过 `@SpringBootApplication(scanBasePackages = "cn.org.openygt")` 扫描所有模块。

### 2.2 Web 拦截设计

类：
- [WebMvcConfig.java](/data2/docker/decoction/openygt-dms-a/dms-app/src/main/java/cn/org/openygt/config/WebMvcConfig.java:1)
- [AuthInterceptor.java](/data2/docker/decoction/openygt-dms-a/dms-common/src/main/java/cn/org/openygt/common/interceptor/AuthInterceptor.java:1)
- [PermissionInterceptor.java](/data2/docker/decoction/openygt-dms-a/dms-rbac/src/main/java/cn/org/openygt/rbac/interceptor/PermissionInterceptor.java:1)

流程：
1. 请求进入 `/api/v1/**`
2. `AuthInterceptor` 校验 Bearer Token
3. 解析用户 ID、用户名、角色并写入 request attribute
4. `PermissionInterceptor` 在存在注解时校验角色

限制：
- 非 `/api/v1/**` 接口未统一纳管。
- `RequiresPermissions` 实际语义为“要求角色”。

### 2.3 数据初始化设计

类：
- [DatabaseInitConfig.java](/data2/docker/decoction/openygt-dms-a/dms-app/src/main/java/cn/org/openygt/config/DatabaseInitConfig.java:1)

流程：
1. 启动时建立 `sys_migration`
2. 按固定数组顺序执行脚本
3. 在 MySQL 场景下对 SQLite 风格 SQL 进行文本替换
4. 记录已执行脚本

限制：
- 脚本列表写死
- 版本号重复无法治理
- 不是标准迁移框架

### 4.2 处方建单设计

流程：
1. 接收处方创建请求
2. 保存处方
3. 自动生成任务
4. 初始化任务状态为待泡药

### 4.3 任务状态流转设计

`TaskServiceImpl` 负责：
- 状态断言
- 状态迁移
- 设备绑定与释放
- 步骤日志写入
- 工时记录
- 状态历史记录

关键方法：
- `startSoak`
- `endSoak`
- `startDecoct`
- `endDecoct`
- `startPour`
- `endPour`
- `startWrap`
- `endWrap`
- `confirmLabel`
- `qualityInspect`
- `handover`
- `forceStatus`

并发设计：
- 包装设备绑定对 `deviceCode.intern()` 做本机同步
- 部分设备读取使用 `selectByIdForUpdate`

限制：
- 分布式部署下本机锁不可扩展
- 状态常量大量使用中文字符串，类型安全一般

### 4.4 消耗流水联动设计

流程：
1. 泡药开始时尝试调用 `ConsumeRecordService`
2. 消耗记录以独立事务写入
3. 写入失败不阻断主任务流转

优点：
- 主流程稳定性优先。

限制：
- 仅记录日志，无完整库存扣减与余额校验。

## 7. 打印模块详细设计

控制器：
- `PrintController`

服务：
- [PrintServiceImpl.java](/data2/docker/decoction/openygt-dms-a/dms-print/src/main/java/cn/org/openygt/print/service/PrintServiceImpl.java:1)

流程：
1. 提交打印任务
2. 判断是否已有活动打印任务
3. 校验打印设备状态
4. 写入 `prt_task`
5. 模拟执行成功
6. 释放设备
7. 写入 `prt_record`

重试流程：
1. 读取最新打印任务
2. 校验最大重试次数
3. 更新重试计数
4. 再次模拟打印

限制：
- 没有异步状态。
- `PRINTING` 状态几乎不会持久存在。

## 10. 主要设计缺陷与改进建议

- 统一 API 前缀与安全拦截范围。
- 将权限注解从“角色校验”升级为“权限码校验”。
- 将数据库迁移改为 Flyway。
- 将状态值从字符串逐步收敛到枚举。
- 将前端菜单改为后端配置驱动。
- 为打印和设备适配补充真实执行器。
